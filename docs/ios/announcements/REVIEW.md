違反文面を出せてしまう。** 投稿のたびにここを通すこと。

⚠️ **`announcements` は Web とアプリで共用していて、出し分けの列が無い**
（2026-07-30 の決定）。**Web 向けに書いたつもりの文面もそのままアプリに出る。**
Web は Apple の審査を受けないので本来は価格の話を書けるが、
**書いた瞬間にアプリ側が 3.1.3(a) に触れる。**

## 公開中の 2 件（2026-08-03 時点でレビュー済み）

### 1. `info` / Collecie をご利用いただきありがとうございます（005）

> このページでは、アプリの新機能や不具合の対応状況をお知らせします。
>
> 新しいお知らせがあるときは、設定画面の「開発者からのお知らせ」に件数が表示されます。

**合格。** 1〜4 に該当なし。

5 も可。**「設定画面の「開発者からのお知らせ」」はアプリに実在する**
（`app/(tabs)/settings.tsx` の `label="開発者からのお知らせ"`、未読の件数付き）。

### 2. `feature` / 支払方法ごとに集金を記録できるようになりました（2026-08-03）

**合格。** 1〜4 に該当なし（金額・プラン名・外部購入・リンクのいずれも無い）。

⚠️ **ただし 5 に軽微なずれが 2 つある。リジェクト事由ではないが、次に直すときに直す。**

**(a) 「収益ページに「支払方法別」のグラフが増えました」**

`支払方法別` は **Web では収益ページのタブ**だが、**アプリではタブではない。**
アプリは絞り込みシートで支払方法を選ぶと、月別売上の内訳の見出しが
`店舗別` → `支払方法別` に変わる（`MonthlyRevenueCard` の `breakdownTitle`）。
**アプリの収益タブは 店舗別 / 月別 / 月別利益 の 3 つで、その名前のタブは無い。**

→ 探しても見つからない、という形で迷う。書くなら
**「支払方法で絞り込むと、支払方法別の内訳が見られます」**。

**(b) 「データの書き出しでも、支払方法ごとに列が分かれます」**

⚠️ **書き出しは有料プランの機能**（`planAtLeast(plan, "pro")`）。無料の利用者には
その導線が無い。**プラン名を書けない**ので「一部のプランで」とも書きづらく、
今回はそのままにしてある（**guideline 上の問題は無い**）。

→ 有料機能に触れるお知らせは、**機能の説明だけに留めて条件を書かない**のが
現状の落としどころ。書けないことを無理に匂わせないこと。

## 投稿するときの手順

```bash
npx supabase link --project-ref <ref>          # ⚠️ .temp があっても毎回要る
npx supabase db query --linked -f docs/ios/announcements/<日付>_<件名>.sql
```

⚠️ **Table Editor に直接打たない。** 上の確認項目を毎回思い出す必要があり、
**何を出したかの記録もどこにも残らない。**

⚠️ **実際に出るかはアプリ / Web で見る。** SQL Editor は service role なので
RLS を素通りし、下書きでも見えてしまう（確認にならない）。

現在の公開状況は SQL で引ける。

```sql
SELECT id, category, title, published, published_at
  FROM public.announcements
 ORDER BY published_at DESC;
```
