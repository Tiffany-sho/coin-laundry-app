## 決定事項（2026-07-27 確定）

以下 6 件は推奨案どおりに確定した。**変更する場合はこの章を更新してから実装すること。**

1. **退会ユーザーの集金記録は残す**（[13.3 アカウント削除](13-app-review.md#133-アカウント削除guideline-511v-必須新規実装)）
   → レコードは削除せず `collect_funds.collecter` を NULL 許容化し、UI では「退会済みユーザー」と表示する。**要 DB マイグレーション**（現状の FK 制約と NOT NULL 有無を実装前に確認すること）。過去の売上履歴に穴を開けないことを優先する。
2. **`collect_funds.date` のランダムジッターは廃止しない（既存データは触らない）**
   → iOS からの新規レコードのみジッターなしで送る。既存レコードは現状維持。同日 2 回集金の並び順は `created_at` を第 2 ソートキーにして解決する。`applyDateRange` は `gte`/`lt` なので日境界の判定には影響しない。
3. **在庫更新はオフライン対応させない**
   → v1 では Outbox の対象外（last-write-wins で他メンバーの更新を巻き戻すリスクがあるため）。運用で困るかを Phase 1 の TestFlight で確認し、必要なら v1.1 で再検討する。
4. **TypeScript はアプリのみ採用**
   → Expo アプリは TS。共有する純粋ロジックと Web は JS のまま（`.d.ts` を添える）。`CLAUDE.md` の「`.jsx` 統一・TS 移行予定なし」は Web の方針として維持する。
5. **v1 は iOS 単独。Android は出さない**
   → Expo なので技術的には可能だが、審査・通知・課金の要件が別。Android は v1 の実績を見てから判断する。
6. **Realtime は入れない**
   → v1 では非対応。必要になった時点で [2章 認可ロジックの配置](02-authz-decision.md) の案A（RLS 移行）を再検討する。その場合も BFF は残し、読み取りだけ RLS 経由に寄せるハイブリッドを取る。
